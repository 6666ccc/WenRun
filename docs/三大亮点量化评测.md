建议简历写成：

1. **Context：** 构建按用途投影、结构化摘要与调用边界预算控制；在 27 个合成上下文场景中保持最新问题与系统规则，100 条、每条 120 字历史场景的估算输入量下降约 81%，并通过 21 项摘要提交、预算与恢复回归。
2. **意图识别：** 实现规则—Jev—大模型级联多标签路由，在 60 条合成样本中，本地接收覆盖率 78.3%、接收样本 Exact Match 97.9%，其余 21.7% 升级推理；保留条件分支、低置信度和域外需求兜底。
3. **HITL：** 为挂号、退号实现人工确认、有效中断匹配及稳定幂等键；通过 32 条确认文本探针、44 项 Python 确认与恢复回归，以及 15 项 Java 挂号业务回归，覆盖确认前无写入、拒绝、旧卡片、重放与业务冲突。

## Context 的实验口径

历史消息数量为 10、50、100；每条长度为 40、120、300 个字符；用途为 chat、knowledge、tools，组合共 27 个。每个历史条目是一条 HumanMessage，并非一组问答。摘要为预先给定的有效结构，不在这轮实验中生成摘要。

对照组：系统规则＋相同用途投影的摘要＋完整历史＋最新问题。实验组：系统规则＋实际 `build_context`＋`assemble_messages` 输出。两组使用相同 `estimate_tokens`，计算 `(对照输入－实验输入)/对照输入`。

| 100 条历史场景 | 完整输入估算 token | 实验输入估算 token | 下降比例 |
| --- | --- | --- | --- |
| 每条 40 字，三个用途 | 4,945～4,971 | 2,497～2,523 | 49.25%～49.50% |
| 每条 120 字，三个用途 | 12,945～12,971 | 2,449～2,475 | 80.92%～81.08% |
| 每条 300 字，三个用途 | 30,945～30,971 | 2,301～2,327 | 92.49%～92.56% |

输入越长，下降越明显。这主要来自历史窗口选择，而不能单独归因于摘要压缩。没有证明被丢弃的信息仍可被模型正确回忆，没有测量摘要生成的额外费用。21 项专项回归验证摘要 ACK、预算失败、恢复与轮次隔离的工程行为，不能替代回答质量评测。

## 意图识别的实验口径与失败案例

固定 60 条中文样本，包含单意图、多意图、静态院务、急症、指代省略、条件分支和域外输入。标签为 chat、knowledge、tools；需要结合历史、条件推理或域外判断的样本另标注 `mustEscalate`。

真实配置使用 Jev `typesafe/jev-1.13`，接收阈值 0.70。规则未接收的 20 条中，3 条被条件门直接升级，其余 17 条调用真实分类器。该阈值是工程配置，不代表经过校准的 70% 正确概率。

- 规则层：覆盖 40/60＝66.67%，接收样本准确率 39/40＝97.50%。
- 加入真实 Jev 后：覆盖 47/60＝78.33%，增加 11.67 个百分点；接收样本准确率 46/47＝97.87%。
- 标记必须升级的 8 条样本均未被本地接收；另外 5 条可分类样本也升级，说明兜底有额外开销。
- 未执行完整大模型路由、Plan、回答或业务工具；“78.33%”仅表示避免后续**意图路由**调用的机会，不能表示项目全部大模型调用减少 78.33%。多意图后续仍可能调用规划和回答模型。

失败样本 I048：“门诊几点开门帮我查排班”。标注为 chat＋tools，规则只返回 tools，遗漏静态院务意图。原样保留，不在同一批评测后调规则再宣传准确率提升。后续修复应新增独立留出样本验证。

## HITL 的实验口径

32 条文本探针：8 条批准、8 条拒绝、16 条普通消息。普通消息包括“确认一下医生是男的吗”“如果没有副作用就同意”“不要取消我的预约”等，均没有直接映射为业务决定。此指标检验确认解析器，不验证完整请求是否携带有效中断、合法身份或执行权限。

44 项 Python 回归由 `test_registration_write_tools.py`、`test_confirmation_kinds.py`、`test_chat_resume.py` 组成，覆盖权威卡片、确认前不写、批准、拒绝、号源失效、Java 不可用、旧中断、多个中断与歧义文本。15 项 Java 回归来自 `RegistrationServiceImplTest`，含幂等重放、跨患者幂等键拒绝、唯一索引冲突、名额释放与并发状态冲突；其中也包含普通挂号及改签逻辑，不应称为“15 种 HITL 场景”。

没有测量用户确认耗时、真实挂号成功率、真实数据库并发重复订单率，也没有执行真实业务写入。因此使用“回归覆盖与通过”表述，不使用“误操作率降低 100%”或“exactly-once”。

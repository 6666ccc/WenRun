# 健康助手独立 AI 工作区设计

日期：2026-08-19  
状态：设计定稿，待写实施计划  
范围：患者端 Vue 3 前端的健康助手壳层与信息架构。  
明确边界：不修改后端接口、鉴权、会话存储策略、流式协议或 AI 工作流；不复制挂号/缴费业务流程；不把健康助手做成无返回入口的独立站点。

本文覆盖并取代 `2026-08-18-frontend-visual-interaction-redesign.md` 中与健康助手壳层冲突的条款，仅限 `/assistant`：

- 原约定「健康助手继续使用统一 AppShell」改为独立 `AssistantShell`。
- 原约定「历史会话只做左上角抽屉、不再叠加第二个永久侧栏」改为桌面常驻会话栏；平板和移动端仍用抽屉。
- 色板、文案、急症提示、结构化确认、业务页 `AppShell` 仍以 8 月 18 日视觉稿为准。

## 1. 结论先行

产品结构是「传统患者服务 + 独立 AI 专注工作区」，共享同一登录态和业务数据。

```text
患者服务首页 / 挂号 / 缴费 / …
        ↓ 点击健康助手
AI 专注工作区（/assistant）
   ├── 返回患者服务（→ /home）
   ├── Logo / 品牌名（→ /home）
   ├── 新对话 / 历史会话 / 标题搜索
   ├── 健康助手聊天
   └── 就诊资料；办理后进入现有业务页
```

一句话体验目标：**点「健康助手」后进入全屏对话工作区；随时能回到医院系统；预约和缴费的最终确认与结果页仍在传统业务页面完成。**

## 2. 已锁定决策

| 项 | 选择 |
|---|---|
| 入口 | 传统页桌面侧栏和移动底栏都保留「健康助手」，点击后进入工作区 |
| 顶栏身份 | 固定文案「温润健康助手」；不暴露模型名；不做模型/助手切换 |
| 会话搜索 | 本轮按会话标题做本地过滤；不搜消息正文；不请求后端 |
| 壳层落地 | 页面内并列换壳：`Assistant.vue` 改包 `AssistantShell`，其它患者页继续包 `AppShell` |
| 返回目标 | 「返回患者服务」、移动端「返回」、Logo/品牌名一律 `router.push('/home')`，不使用浏览器后退 |
| 右栏折叠 | 仅当前页有效；刷新后桌面默认展开 |
| 本轮不做 | 会话重命名、搜消息内容、模型选择器、后端会话隔离、全站根级选壳重构 |

## 3. 架构

### 3.1 两个壳，一套账户

| 单元 | 职责 | 不负责 |
|---|---|---|
| `AppShell.vue` | 传统患者服务：侧栏、面包屑、页脚、移动底栏 | 助手页布局 |
| `MobileTabbar.vue` | 传统页移动主导航，含「助手」入口 | 助手页内导航 |
| `AssistantShell.vue` | 助手全屏布局、顶栏、三栏轨道、右栏折叠、移动顶栏 | 会话、消息、挂号缴费 |
| `Assistant.vue` | 编排对话、历史、资料、确认弹层、跳转业务页 | 不再使用 `AppShell` |
| `useAssistant` | 会话、流式、就诊上下文、任务确认 | 接口与 AI 逻辑不变 |
| `filterSessionsByTitle(sessions, query)` | 纯函数：标题包含匹配（忽略大小写、trim） | 网络请求 |

路由保持 `{ path: '/assistant', component: Assistant.vue, meta: { patient: true } }`。可选增加 `meta.shell: 'assistant'` 供测试或后续识别，本轮不把选壳提升到 `App.vue`。

### 3.2 插槽合同

`AssistantShell` 只决定「放在哪」：

- 默认插槽：中间对话区（欢迎态、消息流、composer、免责声明）
- `#sidebar`：新对话、搜索框、历史列表、删除、会话错误
- `#context`：下一次就诊、待缴费用、最近就诊
- `#header-actions`：移动端「新对话」；桌面顶栏不重复该按钮（新对话在左栏）

壳层自身提供：Logo、品牌名、「温润健康助手」、桌面「返回患者服务」、移动「返回」、右栏收起/展开控件。

### 3.3 数据流

```text
登录用户 ──► useAssistant(user)
                ├── sessions / activeId / sendMessage / newChat / deleteSession
                ├── context（预约、待缴、就诊）
                └── task / pendingInterrupt

Assistant.vue
  ├── query → filterSessionsByTitle(sessions, query) → 侧栏列表
  ├── contextCollapsed（ref，不持久化）
  └── 确认后 router.push('/payment/:id' | '/registration' | '/registration/:id')
```

进入 `/assistant` 时本地会话仍按现有 `wenrun_ai_sessions` 恢复。本轮不改存储键和按用户隔离策略（隔离是独立隐私 TODO）。

## 4. 布局与视觉

视觉借用主流对话产品的「会话栏 + 专注聊天 + 固定输入框」，但使用温润诊所薄荷绿、现有字体和医疗文案，避免用户以为这是通用聊天机器人。

### 4.1 断点

| 宽度 | 形态 |
|---|---|
| ≥1100px | 三栏常驻。左约 240px，中自适应，右约 260px。右栏默认可看，可收起后中间区变宽。 |
| 768–1099px | 只保留中间聊天；左栏、右栏改为抽屉。 |
| <768px | 全屏聊天。顶栏主操作为「返回」和「新对话」，另加历史图标；资料用顶部 chip。不渲染 `MobileTabbar`、面包屑、页脚。详见 4.6。 |

助手页必须占满视口（`min-height: 100vh`），不受 `AppShell` 的 `max-width: 1180px` 和移动底栏 `padding-bottom` 影响。

### 4.2 桌面顶栏

从左到右：

1. Logo +「温润诊所」：可点击，去 `/home`。副文案固定为「患者服务」。
2. 居中或中左：「温润健康助手」（纯文本，不可切换）。
3. 右侧：「返回患者服务」按钮，去 `/home`。

不展示底层模型名、不展示「ChatGPT/Claude」式模型选择器。消息气泡上的「AI 生成」或「温润健康助手」标签可保留，与顶栏名称分开。

### 4.3 左栏（桌面）/ 历史抽屉（窄屏）

顺序固定：

1. 「新对话」主按钮
2. 搜索框，placeholder「搜索会话标题」
3. 「历史会话」列表：标题 + 现有辅助文案「N 条消息」或「空会话」，不新增相对时间
4. 当前会话高亮；删除按钮保持现有「至少保留一个会话」规则
5. `sessionError` 显示在列表底部

搜索：`query` 为空则展示全部；否则标题包含匹配，大小写不敏感。无匹配时列表区文案为「没有匹配的会话」，不关闭当前对话、不新建会话。

### 4.4 中间对话区

复用现有 `Assistant.vue` 行为：

- 无消息：欢迎语「有什么需要帮忙的？」+ 说明 + 4 个患者语言快捷问题 + 输入区「+」快捷入口（预约挂号、待缴费用、就诊记录）
- 有消息：用户气泡、助手正文、引用折叠、流式状态、停止生成
- 输入：自动增高、Enter 发送、Shift+Enter 换行、中文输入法 `isComposing` 不误发送、待确认时禁用输入
- 顶部固定急症提示；命中胸痛/呼吸困难/意识障碍/大量出血时高优先级 `role="alert"`
- 底部常驻：「AI 提供健康信息和就医协助，不替代医生诊断。」

### 4.5 右栏 / 资料抽屉

三张卡片，顺序固定：下一次就诊、待缴费用、最近就诊。数据来自现有 `assistant.context`。点击「查看」打开现有任务弹层（缴费列出账单后跳转；就诊记录跳转挂号列表），不在助手页复制业务表单。

桌面提供「收起 / 展开就诊资料」，按钮必须有可访问名称，不能只靠图标。

### 4.6 窄屏如何打开抽屉

宽度小于 1100px 时左栏、右栏不再常驻，必须有打开方式，但不能把顶栏做成第二套患者导航。

| 宽度 | 历史会话 | 就诊资料 |
|---|---|---|
| 768–1099px | 顶栏图标按钮，`aria-label="打开历史会话"` | 顶栏图标按钮，`aria-label="打开就诊资料"` |
| 小于 768px | 同上，图标无可见文字 | 聊天顶部 2–3 个信息 chip（下一次就诊 / 待缴 / 记录），点击打开资料抽屉；顶栏不再放第四个文字按钮 |

移动顶栏从左到右固定为：返回、历史图标、中间标题「健康助手」、新对话。主操作仍是返回与新对话；历史只以图标出现。不出现患者底栏、面包屑、页脚。

## 5. 进出路径

### 5.1 进入

以下入口全部 `to="/assistant"`，进入后传统壳消失：

- 首页顶栏按钮与服务卡「健康助手」
- `AppShell` 侧栏「健康助手」（保留，供挂号/缴费等页跳入）
- `MobileTabbar`「助手」（仅出现在非助手的传统页）

不新增域名、不新增登录、不单独清会话。

### 5.2 离开（三个回医院出口）

1. 桌面「返回患者服务」、移动「返回」→ `/home`
2. Logo 或「温润诊所」→ `/home`
3. AI 办理预约/缴费并经用户确认后 → 现有 `/registration`、`/registration/:id`、`/payment`、`/payment/:id`；这些页面继续使用 `AppShell`

从业务页可通过侧栏/底栏再次进入助手，看到本地保存的会话。

## 6. 异常处理

| 情况 | 表现 |
|---|---|
| `context.errors.appointments` 等单块失败 | 该卡片文案「暂时无法获取」，其它卡片照常 |
| 删除会话失败 | 侧栏/抽屉底部现有红字，不整页报错 |
| 搜索无结果 | 「没有匹配的会话」 |
| 流式失败、停止生成、待确认 | 保持 `useAssistant` 现有行为 |
| 未登录访问 `/assistant` | 现有路由守卫去 `/login` |

不把前端急症关键词当作医学风险识别已完成；文案只做视觉提醒。

## 7. 无障碍

- 历史抽屉、资料抽屉、任务弹层：`role="dialog"`、焦点陷阱、Esc 关闭、关闭后焦点回到触发按钮。
- 窄屏抽屉打开时 `document.body` 滚动锁定，关闭后恢复。
- 消息流 `aria-live="polite"`；急症条 `role="alert"` 且 `aria-live="assertive"`。
- 「返回」「新对话」「收起就诊资料」「打开历史会话」均有可见或 `aria-label` 名称；点击目标 ≥44px。
- 助手页不渲染患者底栏，避免与 composer 叠层或抢焦点。
- 尊重 `prefers-reduced-motion`：消息滚动与抽屉位移退化为无动画或缩短。

# Agent 等待体验与耗时优化

## 已实现

- 图节点和实际查询工具发出开始、完成、失败、待确认事件。并行步骤分别维护状态，患者可看到科室、医生、号源、医疗资料等查询及真实耗时。
- 进度只使用白名单中文标签；不透传提示词、内部推理、工具参数、异常详情或凭据。
- 有有效任务规划的「医疗知识 + 本院业务」组合按「健康建议 / 就诊安排」输出。医疗部分完成即显示，随后追加就诊结果；最终按同样顺序保存，省去额外的模型改写。其他组合及规划失败仍使用原有汇总路径。
- 检索引用随已完成的医疗段发送并去重。停止或异常时保留浏览器中已收到的正文，同时明确标记未完成；没有 `done` 或 `confirm` 的断流不算成功。
- 公开检索单次请求超时设为 20 秒；单路检索异常返回受控失败提示，避免丢弃其他已成功的检索结果。
- `/v1/metrics/context` 在原有内部鉴权下增加最近 20 次请求的阶段耗时。只含标识、类别、耗时和状态，不含患者文本。

## SSE 兼容方式

保留已有 `status` 类型与 `content`，新增 `step`：

```json
{"type":"status","content":"查询出诊安排与剩余号源","step":{"id":"schedules:example","key":"schedules","label":"查询出诊安排与剩余号源","status":"running","parentId":"business:example","startedAt":0,"elapsedMs":0}}
```

同一个 `id` 原位更新，`parentId` 表示所属步骤。失败步骤不因后续步骤开始而变成成功。父节点耗时包含子步骤，且查询可能并行，不能将所有行耗时相加。旧版字符串进度仍可显示。

## 本地浏览器复测（2026-09-28）

在已登录的 Chrome 普通模式新建会话，用同一虚构成年人的「胃胀反酸咨询 + 建议科室 + 明天上午医生号源」问题，仅查询、不预约。

| 样本 | 首段正文 | 总耗时 | 结果 |
| --- | ---: | ---: | --- |
| 初次新版复测 | 19.500 秒 | 41.855 秒 | 医疗检索失败，只完成业务查询；不作为完整回答性能样本 |
| 加入检索容错 | 36.976 秒 | 48.590 秒 | 医疗建议与号源均返回，一路检索失败后仍保留成功结果 |
| 收紧分段提示词 | 43.560 秒 | 52.733 秒 | 医疗建议与号源均返回，未出现“交给其他助手”的内部话术 |
| 同配置再次复测 | 33.628 秒 | 45.666 秒 | 医疗建议与号源均返回，本轮所有查询完成 |

52.733 秒这一轮：路由 3 毫秒；规划 6.621 秒；医疗节点 36.863 秒；业务节点 8.683 秒；最终拼接 1 毫秒。首段比整轮结束提前约 9 秒。三轮完整回答约 46–53 秒，首段约 34–44 秒；这是少量本地样本，不是延迟保证。

旧版本浏览器观察曾在约 41 秒、67 秒时仍无正文，在约 79 秒、98 秒时已完成；旧数据为间隔截图观察，不是精确计时。模型输出长度、检索可用性也有差异，因此不能据此宣称固定百分比提速。

## 验证与边界

- 后端：`python -m pytest tests/unit tests/test_app.py -q`，282 项通过。
- 前端：`npm test` 81 项通过，`npm run lint`、`npm run build` 通过。覆盖结构化进度、并行状态、失败/确认、停止计时、提前输出、去重及断流。
- Chrome 实测长文本生成中点击停止：正文保留，状态变为“已停止生成”，并显示本轮回答未完成的提示；随后已恢复普通模式与复杂咨询结果页。
- 构建保留原有图表 chunk 超过 500 kB 提示；后端有现有依赖弃用提示。
- 本轮未更换或微调模型。实测路由仅数毫秒，后续应先关注公开检索的稳定性和生成耗时，再用固定问题集比较更快模型/更短输出的质量。
- 进度为本轮实时展示，历史会话重新加载时不恢复整条时间线。停止保留的是浏览器当前已收到的内容。
- 本次是工作区实现和本地复测，不代表对医学回答质量完成系统性评估。

# 前端体验审计（2026-09-21）

## 审计范围

- 产品：温润在线医院患者端前端（Vue 3 + Vite）
- 当前可验证流程：登录 / 注册切换、患者首页、既有 AI 会话、预约挂号、个人档案、就医资料与挂号记录
- 视口：1280×720、375×667、667×375
- 方法：本轮 Codex 内置浏览器截图与 DOM/尺寸检查，结合关键组件源码复核
- 两轮验证：首轮在后端未启动时检查登录与助手失败态；复查时前后端均已启动，并在用户登录后检查真实数据与鉴权流程
- 限制：为避免产生真实医疗操作，本轮没有提交挂号、取消挂号、上传资料或修改档案

## 总体判断

整体视觉语言统一，医疗场景的青绿色调、页面层级、语义控件、键盘焦点和抽屉焦点管理都已有较好基础。登录后的核心流程可以使用，联调期间浏览器控制台也没有捕获到 error / warn。当前最值得投入的不是换一套视觉风格，而是压缩首页常驻输入区、控制挂号结果规模、补齐失败恢复路径，并让 AI 的依据、模式限制和风险提示真正可见、可理解。

## 实施结果（2026-09-21）

本报告中的主要问题已完成实现并通过联调复验：

- 挂号页首次进入默认选择今天或最近有号日期；全部日期最多先渲染 20 条，并通过“再显示 20 个”渐进加载。
- 每个“选择号源”按钮现在包含日期、时段、科室和医生的可访问名称。
- 375×667 手机挂号页由原来的 551 个按钮、约 108,904px 页面高度，降为当天 10 个按钮、约 2,635px；选择全部日期时首批仍只有 20 个按钮。
- 首页推荐问题改为单行横向滚动，输入区主要触控目标提高到 44px；667×375 横屏使用紧凑单行输入布局，同时保留快速模式说明入口。
- AI 失败消息不再直接显示 502 等技术状态码，并提供“重新发送 / 编辑问题”；历史回答中的裸链接按站点名显示，连续参考资料折叠为“参考来源（N）”。
- AI 免责声明提高了文字对比度，“快速模式”的限制改为触屏可打开的内联说明。
- 档案页默认脱敏手机号和患者 ID，完整信息仅显示 30 秒；挂号统计改为“待就诊 N · 历史 N”，技术性空状态改为患者可理解的产品文案。
- 健康趋势图表改为异步资源，`PatientArchive` 主路由 JavaScript 从 545.19kB（gzip 184.26kB）降至 27.77kB（gzip 9.08kB）。ECharts 独立资源仍约 518.88kB，但不再阻塞档案主路由代码加载。
- 登录页只在凭证类错误时标记账号与密码无效；网络或服务错误保持为表单级提示。注册页两个密码框均补充显示/隐藏操作。
- 对话背景增加低对比度“呼吸光晕”，用于缓解大屏空白感；动画只改变透明度与位移，并遵守 `prefers-reduced-motion`。
- 后端已有的 SSE 状态事件现已呈现为可展开的 Agent 处理轨迹：分析问题、拆解请求、检索资料、整理答案与回答完成。进行中自动展开，完成后折叠保留，不展示模型隐藏推理内容。

验证结果：68 个前端测试、ESLint、生产构建全部通过；登录态下再次检查桌面挂号、375×667 手机挂号、667×375 横屏首页、个人档案和真实 Agent 流式进度，功能与布局符合上述结果。

## 本轮流程与健康度

1. 登录页（良好）：品牌、表单和急症提示层级清楚；标签、autocomplete、错误焦点均已实现。
2. 患者首页桌面（需优化）：首屏层级清楚，但 1280×720 下输入区高约 202px，主内容区高约 466px，号源列表末行需要额外滚动才能完整看到。

8. 预约挂号手机（较差）：375×667 下筛选区占据首屏，551 张号源卡全部渲染，文档总高度约 108,904px，查找与浏览成本过高。
9. 个人档案（基本良好）：桌面双栏、手机单栏切换正常，健康数据、运动睡眠、就医资料、我的挂号四个页签均能打开；空状态仍可更明确，隐私信息展示可更克制。
10. 既有 AI 会话（需优化）：回答主体可读，但公开资料会以很长的原始 URL 列表占据对话，且出现简繁体混用，削弱专业感和可扫读性。

## 联调复查新增重点（前后端已启动）

### P1 — 挂号页默认结果规模过大，手机端尤其难以完成查找

证据：

- 默认筛选是“所有日期 / 全部科室 / 全部医生”，一次显示 551 个可预约排班。
- 桌面抽屉和手机独立页都把 551 张卡片同时放入 DOM，没有分页、分组、虚拟滚动或“加载更多”。
- 375×667 下页面总高度约 108,904px；筛选区本身已占据首屏，用户需要长距离滚动才能比较后续日期或科室。
- 这也会放大渲染、样式计算和辅助技术遍历成本。

建议：

1. 首次进入默认选择“今天”或最近有号日期，而不是“所有日期”；顶部显示“今天无号，可查看明天”等可执行提示。
2. 结果按日期分组，先展示 10–20 条；使用分页、加载更多或虚拟列表，并保留筛选条件与滚动位置。
3. 在筛选区增加“共 551 条，当前显示前 20 条”的结果范围反馈；科室与医生筛选支持搜索。
4. 将列表性能测试加入 500+ 号源数据集，至少覆盖首屏渲染时间、DOM 节点量与手机滚动。

相关实现：`frontend/src/components/workspace/RegistrationBooking.vue` 中 `filters` 默认值、`availableSchedules` 以及直接遍历全部结果的 `v-for`。

### P1 — 551 个挂号操作对辅助技术具有相同名称

证据：DOM 中 551 个按钮的可访问名称都只有“选择号源”，读屏用户无法仅通过按钮列表判断要选择哪位医生、哪一天和哪个时段。

建议：为按钮提供包含上下文的可访问名称，例如 `选择 9月21日下午 皮肤科周芳号源`；也可让按钮通过 `aria-describedby` 关联同一卡片的科室、医生、日期、费用与余号。卡片标题建议使用唯一 id，便于建立关联。

### P2 — AI 公开资料呈现过长，语言风格不一致

证据：既有“感冒该吃些什么”回答末尾连续展示多条完整 URL，其中包括很长的参数化链接；正文同时出现简体和繁体中文。来源信息会占据大部分视口，核心建议反而不易回看。

建议：

1. 回答正文只保留简短引用标记，把资料统一收进已有的“查看依据”折叠组件；链接显示站点名和文章标题，不直接显示完整 URL。
2. 对无法结构化为 `message.sources` 的历史消息，在渲染层识别连续链接并折叠为“参考来源（N）”。
3. 在 AI 输出规范中固定简体中文和统一术语；回答先给 3–5 条可执行结论，再给依据。

相关实现：`frontend/src/views/Assistant.vue` 已接入 `CitationList`，但历史回答中的原始链接仍作为 Markdown 正文直接渲染。

### P2 — 个人档案的状态文案与隐私展示可更精确

证据：

- “我的挂号”页顶部显示“0 项待就诊”，下方仍有一张已退号历史卡片；语义本身正确，但快速扫读时容易被理解为“没有任何记录”。
- “运动睡眠”空状态只说明“数据库还未设计”，更像开发状态而不是患者可理解的下一步。
- 档案侧栏默认完整显示手机号和患者 ID；身份证号已脱敏，隐私策略不一致，手机横屏下尤其容易被旁观。

建议：

1. 改为“待就诊 0 · 历史 1”，或将历史记录独立分组并给出明确标题。
2. 将技术性空状态改为“暂未接入运动/睡眠数据”，并说明支持的录入或同步方式；尚未开放的功能可标“即将支持”。
3. 默认脱敏手机号和患者 ID，提供短时“显示完整信息”操作；离开页面或超时后自动恢复脱敏。

相关实现：`frontend/src/components/archive/ArchiveRegistrations.vue`、`frontend/src/components/archive/ArchiveSidebar.vue`。

## 优先问题与建议

### P1 — 短屏和横屏下，常驻输入区挤占核心内容

证据：

- 375×667：顶部 52px + 主内容 256px + 输入区 291px + 底部导航 69px。
- 667×375：顶部 52px + 主内容 53px + 输入区 202px + 底部导航 69px。
- 推荐问题、输入框、三个工具 Chip 和免责声明都放在滚动区之外，使输入区高度直接从主内容区扣除。

建议：

1. 把“推荐问题”移入首页可滚动内容，或改为一行横向滚动，不要作为输入区的永久上半部分。
2. 在 `max-height: 600px` 或横屏媒体查询中使用紧凑输入区：工具按钮收进“更多”，免责声明改为可展开说明，输入区目标高度控制在 96–120px。
3. 对首页首次进入态，允许输入区吸附在底部，但不要让推荐问题和快捷工具同时永久展开。
4. 增加 375×667、667×375 的视觉回归测试，并断言主滚动区有可用的最小高度。

相关实现：`frontend/src/views/Assistant.vue` 的 `chat-page`、`chat-main`、`chat-composer-wrap`；`frontend/src/components/AssistantShell.vue` 的移动端高度计算。

### P1 — AI 安全信息和“快速模式”限制不够可见

证据：

- 免责声明为 12px、`rgb(156,163,175)` 对白色，对比度约 2.54:1，低于普通文本 4.5:1。
- “实时信息”标签为 10px、青绿色对白色，对比度约 3.98:1，也低于普通文本要求。
- 快速模式的重要限制只放在 `title` 文本里；触屏用户通常无法发现 title，视觉上只看到“快速”两个字。

建议：

1. 将免责声明颜色提高到至少 4.5:1，并略增行高；医疗风险提示不应使用最弱的辅助文字层级。
2. 将标签改成“快速模式”，旁边放可点击的信息按钮；首次开启时以内联说明或轻量弹层明确“不能查询本院号源、排班和院内规定”。
3. 模式启用后不要只靠颜色表达，保留勾选图标或“已开启”文字。

### P1 — AI 请求失败没有恢复路径

证据：点击推荐问题后，失败态只显示“暂时没有连接上医院智能体。服务器错误 (502)”和“复制”，没有可执行的下一步。

建议：

1. 在错误消息下增加“重新发送”主操作和“编辑问题”次操作。
2. 对 5xx / 超时使用用户语言，如“助手暂时不可用，请稍后重试”，技术状态码写入日志，不直接占据主文案。
3. 重试时复用同一请求上下文或明确生成新的 requestId，避免重复对话和重复医疗操作。

### P2 — 手机关键控件偏小，不利于医疗场景中的低精度操作

本轮量到的高度：推荐问题约 37px，输入区 Chip 34px，发送按钮 32px，首页快捷任务 40px。它们大多满足 WCAG 2.2 AA 的 24 CSS px 最低要求，但对老年用户、颤抖或单手操作不够友好。

建议：主要操作统一到至少 44×44px；发送按钮优先 40–44px，Chip 高度至少 40px，推荐问题至少 44px，并保留 8px 间距。

### P2 — 登录错误语义需要区分“字段错误”和“系统错误”

当前任何登录错误都会同时把用户名和密码设为 `aria-invalid=true`。当错误实际是服务器 502 或网络失败时，这会错误地告诉辅助技术用户两个字段都无效。

建议：

- 账号或密码校验失败时，再给对应字段设置 `aria-invalid` 和字段级错误。
- 网络、服务端或登录过期使用表单级 `role="alert"`，不要标红字段。
- 注册页两个密码框也可补同样的显示/隐藏能力。

### P2 — 个人档案首访包偏大

生产构建中 `PatientArchive` chunk 为 545.19kB（gzip 184.26kB）。路由本身已懒加载，但健康趋势组件和 ECharts 被同步打入整个档案 chunk，手机首次进入个人档案仍可能出现明显等待。

建议：将 `ArchiveHealthTrend` 改为异步组件，或只在用户进入健康数据/趋势区域时加载 ECharts；同时给图表区保留 skeleton，避免布局跳动。

## 推荐实施顺序

1. 先限制挂号首屏结果量，并补齐每个号源按钮的上下文名称；这是当前对核心业务影响最大的可用性与性能问题。
2. 修短屏/横屏输入区，保证对话和首页任务有稳定的最小可用高度。
3. 同一轮整理 AI 来源、免责声明对比度、快速模式说明和错误重试。
4. 再统一手机控件到 44px 触控目标，修登录错误语义、档案状态文案与隐私脱敏。
5. 最后拆分个人档案图表依赖，改善首访性能。

## 证据边界

- 截图和布局数据来自本轮实际运行的前端，而不是历史截图。
- 首轮的 502 仅用于检查前端失败呈现；联调复查时前端、Java 后端和 AI 服务均已启动，不能用首轮结果评价当前接口稳定性。
- 本轮没有提交挂号、取消挂号、上传资料或修改档案，因此未验证这些具有医疗或数据副作用的最终确认步骤。
- 本轮没有做屏幕阅读器实机朗读、200%/400% 缩放、真实软键盘遮挡和慢网测试，因此不能宣称完整 WCAG 合规。
- Vue 栈专项本地规则库在“响应式固定底栏”与更宽泛的“移动布局响应式”两次检索中都没有匹配项；相关布局建议采用已验证的通用 Web 可用性原则。
